## 💥 一句话卖点

别人刷评论区靠运气翻页，这台机器**每一层漏斗都有实测数据背书**：

| 漏斗层 | 拦截什么 | 实测收益 |
|---|---|---|
| 🔍 按赞排序搜索 | 综合排序混进的低赞尾部 | 结果严格赞降序，头部全是万赞+ |
| 🎞️ 每页 15 条 + 翻页 | 一次搜索接口固有 15 条/页 | 大词跨多页采足高赞池；实测单词采 92 视频 |
| ♻️ 已采去重 | 语义相近词命中的同一批热门视频 | 约 170 次命中去重为 92 唯一视频，省重复抓 |
| 🎯 低于 5 千赞截断 | 首条点赞不足的视频即结束本词 | 实测 `below_floor_n=6` 自然截断，不再固定条数 |
| 🌡️ 评论热度水位早停 | 冷尾翻页（页内最高赞<500 即止损） | 低热视频省一半以上翻页请求 |
| ⛩️ 三级门槛筛选 | 口水、短评、不可成文内容 | 「哈哈哈」再高赞也进不了池子 |
| 🛑 配额达标即停 | 流程自嗨空跑 | 满额立即停止，实测入池 2/2 即停 |

## ✨ 它解决什么

人工刷抖音的痛点是「一台设备、逐条翻、靠运气」，而爆款评论往往**出现在哪并不固定**——可能藏在任何一条视频的评论区。本项目把它变成可工程化的流水线：机器批量喂入海量视频样本，等效「一次刷几百个视频的评论区」，再用层层漏斗把真正**脱离原视频也能成文**的长评筛出来、洗出来、存起来。

### 三条硬原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **样本广而浅** | 宁可关键词多、每条视频评论少，覆盖优先——位置不固定靠覆盖摊平 |
| 2 | **三级门槛缺一不可** | 高互动(≥500赞或≥50回复) → 字数(只计数字中英文、>20字) → 可成文性(AI 自主判定能否写出新的有观点文案)。「哈哈哈」这种短到口水的再高赞也拆不出一句文案骨架，必须淘汰 |
| 3 | **达标即停** | 启动时 + 每词开抓前双重复查当日入池数，满 `--quota` 立即停——流程永不自嗨到跑不完 |

## 🧩 工作流程

```
                    ┌────────────────────────────────────────────┐
   关键词广撒网 ──▶ │ MediaCrawler API 直抓（非浏览器 DOM 模拟）│
   （养生/医学科普 │  默认 --search-sort 1 最多点赞：严格赞降序   │
     /脂肪肝…）    │  搜索接口固有 15 条/页，抓完自动翻页         │
                    └────────────────────────────────────────────┘
                                    │  ▶ 逐关键词循环：
                                    ▼
        ┌───────────────────────────────────────────────────────┐
        │ ⓪ 翻页取样：每页 15 条赞降序 → 已采跳过（skip 去重）    │
        │    低于 5 千赞截断：首条点赞不足即结束本词（替代固定条数）│
        ├───────────────────────────────────────────────────────┤
        │ ① 实时入库 SQLite（loader 幂等导入）                   │
        │ ② 评论翻页热度水位早停（页内最高赞<500 即止损）         │
        │ ③ 三级门槛筛选：like≥500或reply≥50 / 有效字数>20      │
        │    （只计数字中英文）/ AI 判定可成文性                  │
        │ ④ 写入 hits（配额封顶 + 全量去重）                      │
        │ ⑤ 清理采集目录（磁盘零 JSON 残留）                      │
        └───────────────────────────────────────────────────────┘
                                    │
                                    ▼
                  达标即停 —— 每词开抓前复查配额，满额立即停止
                                    │
                                    ▼
              末尾输出当日报告 + 内置 SQLite 数据中心（唯一数据落点）
              accounts/videos/comments/ancestry/batches（原始采集）
              + hits 表（精选爆款命中 / 达标即停依据）
              └─ 累计 / 关联分析 / 跨 Agent 移植
```

> 主路径走**实时 MediaCrawler 采集**（API 签名直抓，首次扫码登录一次后复用缓存；**默认即有头**绑指纹，加 `--headless` 才转无头后台采集）。离线模式仅用于调试排障。
>
> **采集间隔三重防护**：每请求区间抖动（safe 档 6-15s）× 词间休息（默认 90s）× 超稳档 `ultra`（12-28s＋词间 180s，风控期/长跑用）。

## 🔟 十大硬核特性

| 特性 | 说明 |
|------|------|
| 🔍 **默认按赞排序** | `--search-sort 1`（默认）最多点赞降序，配合门槛与按赞止停请求量最少；组合词空桶时切 `--search-sort 0` 综合破空 |
| 🛡️ **默认有头绑指纹** | CDP 会话默认有头（`--headless` 才转无头），扫码重登后绑定可见指纹，显著降空响应反爬 |
| 🎞️ **视频级 5 千门槛** | 点赞<5千的视频跳过评论深挖、按赞止停同步截断；二次遇到若涨过门槛自动恢复抓取 |
| ♻️ **已采智能去重** | 已采视频经 skip 名单跳过；入选命中按「同 comment_id 或同文本」跨天全量去重 |
| 🌡️ **评论热度水位早停** | 页内最高赞<500 且最高回复<50 即停止该视频翻页——冷尾请求全省 |
| ⚡ **逐词实时入库** | 每词抓完秒级导入 SQLite（UPSERT 幂等），中断不丢数据 |
| 🧠 **内存筛选管线** | 聚合+三级门槛全程内存完成，不产生任何中间文件 |
| 🧹 **磁盘零 JSON 残留** | 每词入库后运行目录整段删除，数据唯一落点是 SQLite；入库失败才保留现场 |
| 🛑 **达标即停硬保证** | 启动时 + 每词开抓前双重复查配额，一满立即停 |
| 📊 **当日采集报告** | 逐词统计 / 命中明细（评分·赞回·摘录）/ 库内累计 / 耗时 / 停止原因 |

### 运行中进度汇报

实时采集以前台可轮询方式运行。执行期间每 60 秒汇报一次 Markdown 格式的“本分钟增量 + 累计漏斗 + 当前阶段 + 下一检查点”，并在关键词切换、重试、空结果、入库、清理、配额达标和异常退出时即时汇报。每分钟至少展示视频数、评论数、候选数、命中数、已采跳过数、重试数和配额进度；同时展示最新视频的标题、作者、点赞数、视频评论数，以及最新评论的文本、点赞数和回复数。候选命中需展示点赞、回复、评分和文本片段；没有新增时必须说明是在请求延时、词间休息、登录/浏览器、接口空桶、重试还是入库等待。阶段和最后进度从 SQLite `batches.status/phase/last_progress_at` 读取，不能只看进程是否存活。

实时汇报示例：

```markdown
### 抖音爆款评论采集进度
- **关键词**：`养生`
- **阶段**：实时采集 / 增量入库 / 三级筛选
- **累计漏斗**：视频 **120** | 评论 **860** | 候选 **14** | 新命中 **2** | 当日配额 **2/5**

| 最新视频 | 作者 | 视频点赞 | 视频评论 |
|---|---|---:|---:|
| 养胃习惯分享 | 作者名 | 38,000 | 1,240 |

| 最新评论 | 评论点赞 | 回复数 | 筛选结果 |
|---|---:|---:|---|
| 评论文本片段 | 2,300 | 80 | 已入库 |

**最新候选**：2300赞 / 80回复 / 74分 + 评论文本片段
- **下一检查点**：约 60 秒后；连续无新增将触发停滞熔断。
```

连续两分钟没有任何计数变化时，检查子进程、最近日志、采集目录和 SQLite；空结果率达到 50% 时暂停后续关键词并报告疑似软限流。禁止只说“后台运行中”“一切正常”或只给累计耗时而不提供增量和判断依据。

SQLite 是长期主库，JSONL 只作为采集期间的临时 staging 和入库失败后的重放现场；导入成功后删除 JSONL，失败时保留对应批次目录。

#### 批次状态查询与恢复

运行中可直接查询最近批次，作为每分钟汇报的事实来源：

```bat
python -c "import sqlite3;c=sqlite3.connect(r'sqlite/douyin_hotpool.db');c.row_factory=sqlite3.Row;print([dict(r) for r in c.execute('select batch_id,keyword,status,phase,videos_count,comments_count,skipped_count,retry_count,last_progress_at,error from batches order by started_at desc limit 5')])"
```

状态含义：`collecting` 采集、`ingesting` 原始入库、`screening` 三级筛选、`cleaning` 清理、`completed` 完成、`empty` 无产物、`failed` 失败。`last_progress_at` 超过两分钟未更新时，先检查进程和采集目录；`failed` 批次保留 JSONL，可用 `python sqlite\loader.py --dir <批次目录> --account <slug> --keyword <词>` 重放入库，确认成功后再清理现场。

## 📚 固定筛选门槛

| 门槛 | 固定值 | 说明 |
|------|------|------|
| ① 高互动 | ≥500 赞或 ≥50 回复 | 点赞**或**回复任一达到即过；同时用作评论翻页热度水位 |
| ② 字数 | >20 | 有效字数只计数字与中英文（标点/空白/emoji 不计入），过滤短评 |
| ③ 可成文性 | AI 自主判定 | 唯一标准：能否写出新的、有观点的文案；水贴/提问/接龙/玩梗一票否决（api 未配置时走 Agent 评审队列；异常自动降级规则评分）|
| 视频门槛 | 5000 赞 | 视频级点赞门槛；首个低于门槛的视频结束当前词 |
| 每日配额 | `--quota`，默认 10 | 唯一可调参数，达到即停止整个关键词队列 |

> 生产入口拒绝覆盖上述门槛、频率、排序和翻页参数。

## 🗄️ SQLite 数据中心设计

```
┌────────────┐  1:n   ┌──────────┐  1:n  ┌──────────────┐
│  accounts  │ ─────▶ │  videos  │ ─────▶ │   comments   │
│  creator PK│        │ aweme PK │        │ comment_id PK│
│  昵称/统计 │        │ 标题/互动│        │ 内容/点赞/回复│
└────────────┘        │ 各URL(只URL)│     │ 父子/URL/batch│
                      └──────────┘        └──────┬───────┘
                                                 │ 1:n
                                          ┌──────▼───────┐   ┌──────────────┐
                                          │ ancestry 讨论串│   │    hits 爆款 │
                                          │ 子→父→根/depth│   │  score/理由  │
                                          └──────────────┘   └──────┬───────┘
                                               batches(采集元信息) ─┘
      视图: vw_hot_comments(命中+视频+作者) · vw_threads(讨论串) · vw_daily_stats(每日累计)
```

**设计约束**：
- **幂等**：重复导入同批次不产生重复行（UPSERT），断点续跑与跨天累计天然安全
- **只入 URL**：图片/视频下载链接等大字段仅存 URL 字符串，控制库体积
- **数据不出本地**：库文件不入版本库（`.gitignore` 拦截），克隆后 `db.py --init` 重建空库
